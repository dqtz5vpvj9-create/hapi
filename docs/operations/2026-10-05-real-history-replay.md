# 真实会话滚动回放与修复（2026-10-05）

本轮用真实记录复现了生产版的跳变。修复覆盖历史分组身份、补页位置归属、虚拟节点测量以及缓存尾部覆盖；没有更换主题、输入框或导航。生产发布与最终检查记录在本文末尾。

## 数据和边界

从 Hub 只读获取三份原生会话记录：HAPI Main 2,017 条、o-debug 2,037 条、Windows 会话 17 条。两份 Linux 记录是有界历史切片，不是完整会话。保留服务端实际分页、原生身份、轮次和阶段、工具参数、长正文及附件，另保存 15 张可读取的图片。o-debug 两个附件实际返回 404，采集也遇到过元数据 503；没有用假内容替代。

原始数据和实验构建留在 `/mnt/cache/data-cache/hapi-real-replay-20261005`，不进入 Git 或公开静态目录。回放服务器只绑定 loopback，拒绝业务写操作，不转发到生产、不导入聊天数据库、不触发模型。自动化脚本在 [scripts/testing](../../scripts/testing/README.md)。每次回放冻结采集时的尾部，不模拟将来的 SSE 输出。

## 实际故障及修复

1. **分组变了，用户正在看的 DOM 也换了。** 部分历史页会在已有工具组前面补入工具，原来的控制节点继承首个工具身份，导致整个可见组被替换。现在组控制节点使用自己的稳定身份，工具运行时身份另行保留。首次只读到后半段的轮次，在窗口驻留期间保持已有展示，不因刚发现更早的轮次开头而突然整轮折叠。
2. **位置控制层没有认出适配层正在保留位置。** DSH 基类检查自己的私有分页字段，HAPI 原生适配层却持有另一份保留位置，浏览器布局补偿因此会被当成用户移动。基类改为查询适配层公开的 `preserving` 状态。可见折叠标题本身可以作为锚点；短初始页的实际剩余空间在补页时保留，退出时不会反向夹紧 scrollTop。
3. **网络补页之外，虚拟节点测量也会跳。** Pixel 9 的真实手势记录发现约 38 CSS px 的反向移动，发生时没有应用写入 scrollTop，行高估计正在换成实际值。虚拟列表提供 React DOM 修改前后的回调，由同一个 NativeChatViewport 校正可见节点的坐标。回调没有成为第二个滚动控制器，也不修改 DSH 的采样参数。页提交前的快照只用于明确的补页事务，不能覆盖尚未恢复完成的字符或代码书签。
4. **闭合内容仍消耗运行时工作。** 原实现虽然少挂载外层 DOM，仍为折叠工具构建 assistant-ui 消息/输入运行时。现在完整有界消息源继续提供导航和执行信息，只有展开的展示内容进入消息运行时；展开时通过同一稳定身份恢复工具和交互。
5. **已读取的无正文尾段没有推进缓存游标。** 原生扫描游标可以大于最后一条可显示消息。缓存已经证明这一段读过，但返回游标仍停在最后正文处，导致返回时再次请求已知区间。现在只在覆盖记录确实闭合到 snapshot head 时推进游标，包括空正文后缀；未读取的空洞仍需要请求。

同时保留上一阶段的相邻页预读修正：首次预热一页，完成后按仍然有效的阅读方向重新检查边界；同向惯性可以延续预读。后台空闲不会扫描整段历史。缓存预算仍为每会话 8 MiB、全局 32 MiB，超过预算或版本失效仍可能重新读取。

## 验证记录

生产基线入口为 `index-BYmCdbpv.js`。在同一 Main 切片上，静止读者首轮补页偏移达 1,180.5 px，后续还出现锚点消失。连续 wheel 基线记录过约 582/703 px 的反向移动，证明这份真实数据能够复现问题。

- 修复后的 Main 与 o-debug 各 30 次静止补页，逐帧最大偏移分别为 0.5 和 0.46875 CSS px，未丢失锚点。最终候选包另做桌面 1440 px 宽度的 Main 30 次补页，最大偏移 0.5 px。
- Pixel 9 / Chrome 151 的实际 ADB 手势覆盖连续上滑、跨窗口后反向返回。加入虚拟测量修正后的两次各 60 个手势记录 1,248 和 1,237 帧，均未检测到超过 8 px、与最近输入方向相反的共同节点移动；空白帧均为 0，最多挂载 34 个节点。第二次使用最终候选包。返回时均只有 snapshot head 后的新消息检查，没有重下已访问的历史区间。
- 两次真机帧间隔 p95 为 35.7/37.1 ms，最大为 137.8/144.8 ms。仍有慢帧，不能称为持续 60 FPS。方向检测是诊断指标，不代替肉眼感受，也不保证任意速度和网络下均流畅。
- 17 项浏览器功能流程验证了初始预读不直接发布、跨页连续阅读、缓存返回、End 导航、原生答复身份、停止/失败/无最终答复、工具展开、待回答问题的焦点及草稿、过程书签和大代码块书签恢复。虚拟测量修正后，9 项原生呈现流程再次通过。
- 最终虚拟测量修正后，另 8 项连续预读与往返回归再次通过；31 项投影、滚动跟随、缓存覆盖和局部性检查，以及 Web 类型检查和构建通过。最终包的 o-debug 窄屏 30 次补页仍为最大 0.46875 px；模拟触摸记录 1,966 帧，未发现反向移动或空白帧，但最大帧间隔 424.9 ms，性能验收不能只看位置指标。
- 三份真实切片的工具展开/详情/收起以及输入框草稿检查通过。390 px 截图经过查看，展开的工具仍使用紧凑单行；这项静态检查不替代逐帧轨迹。

原生模拟浏览器与真机结果分开保存。复测必须使用新 tab，或在新文档执行前清理 sessionStorage；在 reload 前清空会被旧页面 pagehide 的书签写回覆盖，导致起始位置不同。
