# 媒体预览加载跳变

2026-10-05，Web 入口 `index-C1UV-_uP.js`。仅发布 Web，Hub、Runner 和原生引擎未重启。

## 原因与修改

ArtifactCard 在请求前、取得 blob 地址后、图片解码后使用不同高度。用户附件也没有预留图像布局。文件预览与 PDF 的加载结果继续撑高正文；异步出现的标题操作按钮还可能让窄屏标题换行。

本次为缺少尺寸元数据的图片使用响应式稳定预览区域，按比例完整显示，点击使用原有查看器。加载、错误、重试和解码均不改变区域尺寸。文件预览在用户打开时预留区域，随后内容在区域内滚动；标题操作的位置提前保留。HTML sandbox 与下载安全处理保持不变。

这不是完整的多模态体验改造。当前协议不含图片宽高，预览框不能在第一次请求前匹配每张原图的比例；本次没有添加尺寸服务或修改协议，也没有通过增加延时、定时滚动或重复补偿掩盖布局变化。

## 验证与限制

- 新增 `e2e/media-layout-stability.spec.ts`，对 390 px 与 1280 px 两种宽度回放延迟的横图、长图、用户附件及长文档，采样 120 帧，检查正文偏移不超过 1 CSS 像素，并验证图片打开／关闭。
- 图片查看器、资源卡和生成媒体的 14 项相关单元测试分批通过，Web 类型检查及构建通过；窄屏截图已实际查看。
- 12 项浏览器扩展回归中 11 项通过，长代码书签恢复出现一次 486 px 偏移。该失败与上一轮已有的同一失败一致；本次未改变滚动控制。单独复测结果保存在下述日志中，不能据复测通过宣布偶发问题消失。
- 本轮浏览器手机尺寸模拟不等同于重新完成 Pixel 9 真机验收。
