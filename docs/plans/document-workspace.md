## 本轮实现与证据

已补齐 Codex `:codex-file-citation{…}` 的显示和点击路径，复用原会话文档入口；v19 真实引用到 20 页 PPT 的桌面/窄屏流程已验证。

Office 首屏不再等待完整 PDF 下载。Hub 返回经会话授权的预览句柄，PDF.js 按需读取字节段，Worker 与转换并行启动。真实 Choreo v18 的 PDF 为 24,201,257 字节 / 20 页；在 4 Mbps、40 ms 限速模拟下，预览请求到首屏的单次比较从 72.8 秒降到 9.8 秒，新版首屏约 0.9 MB。首次转换仍需数秒，不宣称即时打开或用户设备已达到该数值。

文档现已作为 `document` 资源接入现有 tmux 分屏树。文件卡、正文路径、文件树统一打开同一个查看器；重复打开聚焦原窗格，干净且未固定的预览可复用。MD/TXT 等 UTF-8 文本可编辑、保存、查找、撤销，并把选区附到原会话草稿。Office 通过 Hub 上的 LibreOffice 转成静态 PDF，PDF.js 提供分页、缩放、文字层和框选。表格用 SheetJS Worker 读取、Glide Data Grid 显示和选择单元格；图片支持区域引用。

实现有以下明确边界：

1. 保存沿用已有 `expectedHash`。HAPI 进程之间用同一个规范化文件路径上的 `proper-lockfile` 互斥；写入临时文件后再次比较版本，再替换原文件。外部编辑器或 agent 的 shell 命令不参加该锁，最后一次比较到替换之间仍存在竞争窗口。**不能把本轮保存实现称为对任意外部写入的原子比较交换；原设计要求的外部写入所有权协调尚未完成。**
2. 文本草稿按服务器、用户、命名空间、机器和文件身份保存在本机 IndexedDB。温缓存内保留光标与撤销栈；刷新恢复文本和基准版本，不恢复撤销栈。不能无损往返的编码、混合换行和大于 4 MiB 的文本不开放原文件覆盖。读取上限为 64 MiB。
3. 复访使用当前内容；可见文档定期及重新激活时查询文件大小/修改时间。发现变化只提示，用户明确重新读取后才换内容；有草稿时保留草稿并提示冲突。这比原计划中“干净预览自动切换”更保守。MD 当前为预览/编辑切换，尚未增加同时分栏。
4. 文档温缓存以 8 个条目和 64 MiB 为淘汰目标；活动文档、保存中内容及尚未可靠落盘的草稿受保护，不宣称所有情况下总内存严格小于该值。Office 派生缓存为 12 项/96 MiB，串行转换且最多 4 个待处理任务。工作簿在 Worker 中读取，限制 16 MiB、50 个工作表、512 列及 50 万个已填充单元格。
5. 路径文件引用携带实际读取版本。无版本元数据的 opaque artifact 只提供资源 ID，并明确标记版本不可用。Markdown 预览引用源码块范围；源码编辑器提供精确字符范围，按 LF 规范化后的 UTF-16 索引解释。Office 页码/区域是预览定位，不冒充源文档对象 ID。
6. 文档窗格关闭、替换及单会话文件页的返回按钮具备保存/保留/放弃决策；浏览器级刷新提供离开提示，草稿独立持久化。浏览器历史导航没有额外的自定义关闭对话框。Windows 原文件、ACL 与生产保存链路已验证；Pixel 9 真机、中文 IME 和断网跨设备流程仍待实机验收。模拟 API 测试和生产浏览器记录分别保存。

运行 Office 预览需要 Hub 机器安装 `soffice`（可用 `HAPI_OFFICE_BINARY` 指定）。本机部署时设置 `HAPI_DOCUMENT_TEMP_DIR=/mnt/cache/data-cache`；每次转换使用独立临时 profile，任务结束清理派生临时目录。配置已禁用宏与链接更新，并有 60 秒超时；独立 profile 不是操作系统沙箱，尚未验证独立容器资源隔离。PPT/Word 原文件仍经所属机器现有 Runner 授权读取，不交给公共预览服务。

布局协议已扩展为 schema 2；上线时需要协调 CLI、Hub、Web，不能单独更新网页后声称远端保存已可用。已协调发布 CLI、Hub、Web；本轮未提交或推送源码。下面第 1–10 节保留经审查的设计基线；遇到“待实现/候选/现有”等表述时，以本节的实际状态和边界为准。

本计划依据用户最新要求：Office 文档不需要直接编辑，但 Markdown、TXT 等纯文本需要直接编辑。所有支持选区的格式都可以把选区附到当前会话，请求 agent 修改原文件。HTML 审查页见 [Lavish 设计页](../../.lavish/document-workspace-plan.html)。

## 1. 用户看到的工作流

聊天中的交付物是紧凑文件卡，显示名称、类型，以及打开、下载入口。点击文件卡、正文文件链接或文件树，都打开同一文档工作区。工具为检查结果而读取的图片仍可查看，但不自动成为交付物；不能仅凭后缀推断资源用途，也不因为资源位于过程分组中就隐藏真正的交付物。

tmux 工作区中，文档成为与聊天、终端平级的第三种窗格资源，复用 WorkspaceShell 的分屏树、移动、放大、底栏与手机 P1/P2 投影。文档不再嵌套在聊天窗格的 SessionWorkspace 内部。普通单会话模式仍可用现有 SessionWorkspace 容器承载同一个文档组件，不另建查看器。

点击文档保留来源聊天，首次在其旁边打开文档窗格；重复打开同一文档聚焦已有窗格。继续打开不同文件时，复用本机为该来源会话记录的、未固定且没有未保存修改的预览窗格，避免每次点击都增加分屏。开始编辑或主动保留后固定该文档，不再自动替换。手机仍使用同一布局数据，仅投影当前文档窗格，不新增另一套路由栈和返回导航。正文不插入大尺寸阅读器，也不覆盖其他聊天或终端。完整的 tmux 接入设计见第 10 节。

工具栏只保留文件名、与格式有关的操作和更多菜单：

- Markdown：预览 / 编辑、保存、查找；桌面可以按需并排预览。
- TXT / 代码 / 配置：文本编辑器、保存、查找。修改由用户主动保存。
- PPT / Word / PDF：页码、缩放、选择文字 / 框选、下载。
- Excel：工作表、名称框或选区地址、查找、下载。

选中文字、单元格或页面区域后，附近出现“请求修改”。点击后生成可检查的引用卡，放入**原会话现有输入框的草稿**，由用户补充要求并发送。选择本身不发送消息，也不新建会话。手机先保存选区，再切到输入区，避免键盘弹出导致选区丢失。

| TXT / 源码 / 配置 | 可查找、带行号的文本 | 是，权限、编码与完整内容允许时 | 文件版本、字符区间、行列、原文 | 复用 CodeMirror；新增保存、草稿与冲突流程 |

这里的“直接编辑”指编辑磁盘上的原文本文件，而不是修改聊天记录中的代码块。HTML 源码也属于文本，但 HTML 预览继续在现有隔离边界内运行；不能为了读取选区而解除 iframe 隔离。跨隔离页面的语义选区需单独适配，不列为首批承诺。音视频、压缩包继续使用已有播放或下载入口。

Excel 不能统一降成 PDF 后假装具备单元格选择。数据查看与版式查看是两种能力：首批数据视图明确告知格式、图表和公式计算的限制；如果提供版式 PDF，则其选择是页内区域，不伪造成 B2:D8。没有缓存计算结果的公式显示公式本身及结果不可用，不能显示编造的值。

## 4. 组件与数据边界

数据流为：

`现有文件/资源入口 → WorkspaceStore 打开 document 窗格 → DocumentPane → Viewer/Editor → SelectionReference → 明确关联会话的 composer → 现有发送流程`

实现现集中在 `web/src/documents/`；以下为设计时划分的职责，具体模块对应关系见文首：

- **DocumentPane / DocumentSurface**：前者连接 WorkspaceShell 的窗格生命周期，后者提供工具栏、查看/编辑和加载状态，可在普通单会话容器中复用。分屏几何继续只由 WorkspaceShell 管理。
- **DocumentSource**：统一 machine、session、已授权资源路径与读取版本。返回完整性、编码与读写能力。文件名不是资源身份。
- **ViewerAdapter / EditorAdapter**：声明 textSelection、regionSelection、cellSelection、editable 等实际能力；提供准备就绪、定位和选择结果。菜单只显示当前适配器支持的操作。
- **DocumentSession**：缓存当前读取版本、阅读位置、选择、编辑器撤销历史和草稿。活动文档与最近使用文档有界保留；脏草稿先可靠保存，不能因 LRU 淘汰消失。
- **SelectionReference**：与查看器无关的引用对象，经现有发送流程交给 agent。它是用户请求的上下文，不是另一次模型调用。

Office 转换在受控后端任务中执行，不在浏览器主线程转换。Linux 与 Windows 的源文件仍通过各自已有 Runner 的授权读取边界取得。具体转换部署在 Hub 所在服务还是独立任务进程，应以真实 PPT 的字体与排版验证决定；浏览器不能直接把私有文件交给公共 Office 预览服务。

转换只产生可淘汰的预览派生物，不另建聊天数据库或改写原 Office 文件。相同原文件版本和渲染配置的任务合并；缓存容量同时受字节和条目上限控制。转换引擎或字体集变化必须使旧派生结果失效，版本标识复用已有机制，不增加多重校验系统。

## 5. 文本编辑的完整闭环

首次打开 MD 默认预览，进入“编辑”后用 CodeMirror 编辑源码；TXT、源码、配置直接进入文本编辑视图。无写权限时明确只读。格式未知、编码不能无损往返、只读取了文件的一部分时，不开放原文件覆盖保存。

保存由按钮或 Ctrl/Cmd+S 触发，快捷键只在编辑器拥有焦点时生效。中文输入法合成过程中不误提交、不截断组合文字。换行、BOM 和原编码能够保留才进行写回，不静默把 CRLF 或非 UTF-8 文件改成另一种格式。

状态必须能区分：未修改、未保存、保存中、已保存、保存失败、版本冲突。保存中的新输入属于下一份草稿；前一次响应不能把后一次输入标成已保存。断网保留草稿；响应丢失时不能武断显示成功，也不能无条件重发覆盖写入。

草稿按用户、机器和文件身份隔离，基于原读取版本恢复；切换文档保留撤销历史与光标，重载恢复草稿但不伪造旧的撤销栈。遵守现有本地草稿与退出登录清理规则。接入 `usePaneEditing`，避免远端工作区同步卸载有未保存内容的编辑器。关闭未保存文档时提供保存、保留草稿、放弃修改三种清楚的结果。

复用现有 `expectedHash` 写入约定，读取时提供与返回字节一致的基准版本；不另增第二套 hash 协议。所有 HAPI 写入按文件串行，保存前拒绝已变化的基准，使用安全的文件替换流程，并保留当前权限边界。冲突界面展示“原版本 / 我的草稿 / 磁盘最新版本”，由用户审查合并结果，不静默选任意一方覆盖。

**并发边界必须实测：**原生 agent 或外部编辑器可能绕过 HAPI 的串行队列；“校验后原子替换”仍不等于与外部写入原子比较交换。实现阶段必须检查能否复用文件所有权/锁机制，并用检查与写入之间的并发用例验证。若不能协调某个已知写入方，先禁止该文件的并行覆盖保存，保留草稿和导出副本。不能用“有版本校验”宣称所有外部竞争都已解决，也不因此停止整个 agent 会话。

有未保存编辑时点击“请求修改”，默认明确使用“保存并引用”。保存成功才把选区与新文件版本附到输入框；保存失败或冲突时保留编辑与选择，不发送请求。用户也可以回到已保存版本后引用。不会把未保存文字标成磁盘内容，也不会在点击选区操作时偷偷覆盖文件。

## 6. 选区需要带什么

基础身份：原会话/pane、机器、文件或 artifact 引用、原文件版本、展示版本，以及用户能读懂的文件名和位置。位置使用区分格式的结构：

| 选区 | 定位依据 | 补充上下文 |
| --- | --- | --- |
| 文本 | UTF-16 字符区间 + 行列（约定区间端点） | 精确原文、必要的前后文；换行语义一致 |
| 渲染 MD | 源码块范围；可靠时增加精确字符区间 | 被选的可见文字；不把 DOM offset 当 Markdown offset |
| PPT / Word / PDF | 页或幻灯片、相对页坐标的区域 | 可提取文字、少量上下文；必要时附选区图 |
| 工作表 | 工作表名称 + 单元格范围 | 显示值、可用公式；不发整本工作簿 |
| 图片 | 相对原始图片的区域 | 图片引用，必要时附选区图 |

agent 以原文件为修改目标，PDF/选区图只是定位依据。幻灯片插入、文字重排、工作表重命名后，旧页码和坐标不可自动沿用：引用卡保留原版本，提示文件已变化，由用户重新选择或明确仍引用旧版本。没有稳定定位时，降为“该文件 + 引用文字/截图”，不能伪造对象 ID。

在 composer 中每个引用可查看、定位、移除；可以引用多个区域。引用内容只随用户点击发送进入消息。复用现有附件、确认与发送队列；不能因新增结构化上下文改变已处理消息的判定或产生重复发送。非原生 Codex agent 的引用承载能力需在实现阶段验证，未验证前不承诺相同的多模态定位精度。

## 7. 局部性、更新与安全边界

聊天滚动容器与文档滚动容器各自只有一个位置控制者。文档翻页、变高、保存、切换预览不能触发聊天滚底或重建整个消息列表。文档内部的页码、缩放、光标恢复不改变用户已确认的“切回会话看最新内容”策略。

复访先显示最近缓存，再后台检查版本；已显示内容不因同步重新空白。PDF/图片在尺寸已知时预留正确比例，长文本、页面与表格按需挂载。缓存内容有界，未保存草稿另行持久保护；不为保留最近文档而长期保留所有 canvas。

有选择、正在编辑或处理冲突时，新文件版本只提示“文件已更新”，不替换读者眼下的内容。干净文档准备好新预览后再切换，并保留合理的页/缩放位置；页已不存在时明确说明。旧会话/旧文件的读取和转换结果不能更新新面板。

加载状态区分读取、转换、渲染和失败。短暂同步沿用超过 1 秒才显示的提示；只有真实可测的字节或页数才显示进度，转换阶段不展示虚构百分比。错误简短描述并提供重试，诊断细节按需展开。

保留当前命名空间、机器归属、路径权限和 HTML 隔离。Office 宏不执行；转换任务限制运行时间与资源，文件在任务结束后按现有临时文件政策清理。不通过 public URL 暴露私有源文件以换取第三方预览。

## 9. 实现顺序与验收门槛

1. **验证关键样本。** 用真实 Choreo PPT、带表格/代码的 MD、UTF-8/CRLF 文本和多工作表 Excel，验证转换与选区方案。记录哪些格式能准确定位，哪些只有截图/引用兜底。先解决字体保真和选区映射问题，再固定 Office 依赖。
2. **打通文档工作区与文本编辑。** 统一三个入口，接入 pane 归属；实现 MD/TXT 编辑、版本化读取、保存、草稿、冲突与文本选区。修正现有路径问题，贯通 CLI/Hub/Web，不将写权限扩大到整个机器。
3. **接入 Office / PDF / 图片。** 建立转换任务与派生缓存，页/区域选区、引用卡和原会话发送流程。Excel 走独立 sheet/cell 适配，不冒用 PDF 定位。
4. **整体验收再发布。** Linux 和 Windows 原文件、桌面 Chrome、Pixel 9 Chrome 分别留下结果。设计截图、单元测试、构建、真实文件操作不能互相替代。

必须覆盖的行为：

- 修改 MD/TXT 后保存并重新打开，字节/内容符合用户编辑；撤销、中文输入法、CRLF/BOM、只读、截断读取、保存失败和刷新草稿都有明确结果。
- 两个面板编辑同一文件，以及 agent 在读取后、保存前、保存期间写入的竞争；不得把过期草稿静默标成成功保存。
- 缩放、滚动、窄屏、虚拟页面卸载后，文字/区域/单元格引用仍指向原选区；先切会话再等读取完成，不串到新会话。
- “保存并引用”失败不发消息，选区请求进入现有草稿；引用不自动发送、重连不重复发送。
- 文件在选区后被修改、删除或临时图被清理，提示真实状态，不无限加载或悄悄定位另一处。
- 打开/关闭文档、输入法弹出、预览更新和转换完成时，聊天阅读锚点、补页、消息顺序和输入焦点保持原有约定。
- 缓存复访、首次预览、转换等待、长文档滚动与内存分别测量；缓存和挂载有界，不以固定 FPS 或毫秒数作未测承诺。

涉及共享协议时执行仓库完整类型检查、测试和受影响的原生一致性检查。只完成本设计文档时，检查文字、链接、桌面/窄屏布局；不把设计页验证记为功能通过。

## 10. 落到当前 tmux 窗格架构

本节依据 2026-10-07 工作树源码复核，修正最初“复用 SessionWorkspace 做所有分栏”的表述。现有 Web 工作区使用 FlexLayout 适配 HAPI 自己的分屏树，并非依赖操作系统 tmux 进程显示文档。已有 `WorkspaceDocument` 指布局集合中的一个工作区，不是 Office/文本文件，新增类型必须避免混淆。

### 10.1 资源与打开意图

`PaneResource` 当前只有 chat、terminal、empty。增加 document 分支，同时更新 Zod、sameResource、唯一性约束、序列化、布局标题与资源权限校验；不能只在 WorkspacePane 的 JSX 加一个组件。

文档资源保存来源引用：工作区文件使用已授权的 sourceSessionId、机器及规范化路径；独立 artifact 使用所属 session 与 artifactId。机器与路径由源读取链路校验，客户端声明不是权限依据。文件身份按 namespace + machine + 规范化路径区分，artifact 按其现有稳定身份区分；两个同名文件不能合并，同一文件经不同入口打开不能无谓复制编辑器。直接编辑限可写源文件，artifact 有预览字节不等于拥有原文件写权限。

原文件内容版本留在 DocumentSession，页码/选区/草稿也不写入布局树。新增格式需升级布局 schema，并迁移既有布局与本机待发操作；不清空用户工作区。旧网页不能理解 document 时应要求更新，不能把未知资源丢弃后覆盖共享树。

拟新增 `openDocument({ sourcePaneId, expectedSource, documentRef, intent })`：

1. 点击时固定来源 pane、资源绑定与请求目标会话。重复打开默认聚焦已有文档；沿用当前“一资源一个窗格”的约束，首版不新增同一文档的重复编辑视图。
2. 首次在来源聊天旁边创建 document 窗格；以后优先复用为该来源会话记录的预览窗格，只允许替换未固定且无未保存修改的文档。编辑自动固定，也提供主动保留；需要并看时显式“在旁边打开”。不替换聊天、终端或脏文档。现有 split/layout 表达新增结构，bind 表达经过检查的预览替换，不增加第二套标签栏。预览槽位与固定偏好属于本机打开意图，替换前仍检查共享树中的实际绑定。
3. 新增显式以 paneId 为目标的打开方法。现有 `split()` 使用当前 focusedPane，异步文件解析完成后不能直接调用它，否则用户已换焦点时会在错误窗格旁分屏。
4. 读取晚到时验证来源绑定和文档绑定；已取消、关闭或更换的目标不再接收结果。所有三个入口走这一方法，不能分别保留全局路由、模态框和内层工具面板三种打开方式。

### 10.2 窗格内容与界面

`WorkspacePane` 明确按 chat / terminal / document / empty 分支。当前代码把非空、非终端资源都交给 SessionWorkspace，新增文档时必须移除这一隐含兜底。SessionPaneController、NativeCodexThread 和聊天消息 store 保持职责不变。

`layoutAdapter` 的标题改为按资源解析；文档显示文件名和类型，未保存标记属于本机 UI。重复编辑、翻页和每次按键不触发布局 model 重建。移动只改变树中位置，paneId 与文档身份保持稳定。即使跨工作区移动导致 React 宿主重新挂载，也必须从独立 DocumentSession 恢复状态，不能仅依赖“key 没变就不会卸载”。

文档窗格使用已有紧凑标题与 1px 分隔线，内部只有文件必需工具栏。Office 放页码、缩放、选区，MD/TXT 放预览/编辑、保存、查找；文档里不复制聊天 composer、模型、Goal 或权限状态栏。Ctrl-b 方向焦点/放大/移动沿用，Ctrl/Cmd+S 仅在文档编辑器处理；输入法合成与终端按键透传要保持原约定。

手机沿用 `WorkspaceLayout` 对当前 pane 的放大投影和底栏 P 按钮。底栏需要区分聊天/终端/文档图标，并可读出文档名；不用聊天运行状态冒充文档保存状态。文件菜单与保存入口放文档工具栏，不恢复已被用户移除的应用顶栏。

### 10.3 请求修改的会话归属

“文件来自哪里”与“请求发给谁”分开。DocumentSession 的本机 view state 保存本次打开行为明确带来的 requestTargetSessionId，初次恢复默认使用资源的来源会话；它不参与文档唯一性判断。单纯切焦点、移动窗格不改变目标。

从另一个聊天显式打开同一文件时，聚焦原文档，并把新的请求目标清楚显示在“请求修改 → 会话名”上；不因当前 focusedPane 是另一个聊天而暗中改目标。选区带上文件版本、位置与 requestTarget，再追加到该会话草稿，不覆盖用户原有文字和附件。

`SelectionReference → 原会话草稿存储 → 聚焦其 chat pane → 现有发送流程`。若聊天在另一工作区，使用已有定位与聚焦；若用户已关闭其视图，先保存引用草稿，再提供重新打开原会话的入口，不能占用当前其他聊天，也不能自动新建 agent。原会话发生已确认的 superseding/handoff 时按已有身份转移路径迁移，不能凭标题或机器相同选择接收者。

### 10.4 状态分层与持久化

| 状态 | 放在哪里 | 是否跨设备同步 |
| --- | --- | --- |
| 分屏树、paneId、文档资源引用、工作区名称 | 现有 WorkspaceSnapshot / Hub 布局存储 | 是，复用 revision、操作 ID 与 SSE |
| 当前焦点、放大、文档页码/缩放、光标、选区、请求目标 | 本机窗格/文档状态 | 否 |
| 未保存草稿、读取基准、保存事务状态 | 独立于 React 挂载的 DocumentSession 与本机持久草稿 | 否；不能塞进 workspace localStorage JSON |
| 原文件内容 | 来源机器 | 通过文件读写接口访问；不是布局同步 |
| Office 派生预览与已读取字节 | 有界派生/读取缓存 | 按授权访问；不随每次布局变更传输 |

因此电脑打开文件后，手机可从同步的文档窗格读同一原文件；电脑未保存的输入不会伪装成手机已读到的磁盘版本。这不是协同编辑功能。

### 10.5 必须补的生命周期缺口

- **本机关闭与替换。** 当前 `closePane()`、`closeWorkspace()`、`bind()` 不执行可异步决定的保存流程。`beforeHide` 只是采集位置，`editing` 是查询状态，不是关闭拦截。新增窗格级离开协调：保存、保留草稿或放弃，再执行既有命令；取消或保存失败就不关闭。侧栏选新会话覆盖当前文档也必须经过这一入口。纯移动/焦点切换不要求保存。
- **远端关闭后台编辑器。** 当前 `receive()` 主要检查 active workspace 的 editing callbacks；后台已卸载文档没有回调。远端布局到达时应查询独立 DocumentSession 的脏状态，覆盖所有相关文档。复用已有本机 temporary view，保护草稿并让其他窗格继续同步，不把本机保护视图自动写回共享布局。
- **常驻视图与大文件成本。** 当前预算按 pane 数量，且保留刚离开的工作区；它不是 PDF 页数或字节上限。继续保留聊天既有热切换政策，文档另加有界页面/字节缓存，隐藏后暂停渲染与观察，回收远离视口的 canvas。不能靠无限保留编辑器 DOM 保住草稿，也不能让文档释放逻辑驱逐当前可见聊天的正文。
- **焦点与订阅。** 当前 WorkspacePane 会按非空资源取 session，并将聚焦会话标为已读。文档聚焦不能冒充读过关联聊天；聊天可见集合只统计 chat 窗格。文档前后台信号控制读取/渲染，不复用聊天 syncTailMessages，也不触发聊天首屏定位。
- **服务端授权。** 当前工作区接口只验证非空资源的 session 命名空间。新增文档需继续验证来源归属，并在实际读取/保存时走原路径权限；共享了一个路径引用不等于任何机器可写这个路径。保存继续补齐第 5 节的现有 RPC 缺口。

### 10.6 可执行的接入顺序

1. 扩展 shared 资源类型及迁移、Hub 校验、sameResource；加入 document pane 和统一打开意图，用只读现有文本/PDF 内容验证分屏、移动、手机投影。
2. 建立 DocumentSession 与草稿持久化，接入本机关闭/替换及所有后台文档的远端关闭保护；再开放 MD/TXT 保存。
3. 将 SelectionReference 追加到原会话草稿，验证异步切焦点、关闭聊天、会话 handoff、多个机器同名文件，之后接入 Office/表格选区。
4. 使用现有 workspace lifecycle/sync/resume 与聊天历史测试入口扩展混合窗格场景：聊天 + MD + PPT + 终端，重复切换、跨工作区移动、远端关闭后台脏文档、弱网保存与重连。记录实际挂载与缓存字节，不能仅以最终截图通过验收。
