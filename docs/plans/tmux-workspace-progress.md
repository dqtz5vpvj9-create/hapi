## 共享工作区后端

`@hapi/protocol/workspaces` 定义严格的结构和资源引用，以及创建、导入、重命名、分屏、绑定、移动、关闭、还原和几何变更命令。布局文档不包含聊天正文、草稿、焦点或阅读位置。

Hub 数据库由 v28 迁移至 v29，新增 namespace 内的布局集合和已处理操作 ID。一个集合 revision 让跨两个工作区移动只占一次 SQLite 事务：冲突返回最新文档，由客户端重放仍适用的意图。几何命令不能改资源绑定；窗格成员变化后不能使用旧树覆盖新布局。

操作 ID 使用普通唯一主键，解决“服务器已提交、HTTP 响应丢失、客户端重试”的明确故障情形。重试返回当前文档，不重新执行，避免把后来关闭的工作区重新创建。身份校验继续由 JWT 和 namespace 负责；新聊天资源引用必须通过会话 namespace 校验。

API 为 `GET /api/workspaces` 和 `POST /api/workspaces/operations`。提交后通过已有全局 SSE 广播 `workspaces-updated` revision。八个有认证的 API 流程已验证两设备冲突、移动的原子性、丢响应重试、关闭后旧几何重放、晚到绑定、关闭撤销、namespace 隔离，以及数据库迁移和重启后的持久性。Hub 全量测试通过（1,449 项通过，3 项既有集成测试跳过），所有包类型检查通过。

Web 已接入同步协议。离线意图持久化、丢响应后的幂等重试、版本冲突重放及远端关闭/替换正在编辑的窗格时保留本机临时视图，已通过 6 条传输故障测试和 4 条真实认证 Hub/双浏览器流程。后者使用真实 HTTP、SSE 和 SQLite，但聊天内容来自 fixture。线上另行验证了两台机器的既有聊天分屏、两浏览器布局共享、手机 P1/P2 切换和刷新恢复；未把这些结果扩展为长期终端或真实手机键盘验收。
