## 已接入的产品能力

工作区是独立的视图模式，与主题选择无关。侧栏的视图按钮进入工作区；底栏的单会话按钮返回当前聊天。再次进入恢复先前的本机布局。普通会话链接继续打开单屏。FlexLayout 0.11.1 只管理分屏几何和挂载，聊天正文继续使用现有 NativeCodexThread / HappyThread。

多个工作区可各自容纳聊天和独立终端窗格。普通点击未打开的会话替换当前窗格；已打开的会话只切到原窗格。侧栏菜单“在旁边打开”和拖到边缘新增分屏，窗格标题可拖动重排，分隔条可调大小。窗格菜单提供放大、还原、移动到另一工作区和关闭。底栏可新建、重命名、关闭和恢复最近关闭的工作区。

默认快捷键使用 Ctrl-b 前缀：`%` 左右分屏，`"` 上下分屏，方向键切焦点，`o` 轮换窗格，`z` 放大还原，`x` 关闭视图，`c` 新建工作区，`n` / `p` 切工作区，`1`—`9` 直接选择。两次 Ctrl-b 将第二次交给终端。底栏上的滚轮切换工作区，正文滚轮仍用于阅读。

窄屏显示当前工作区的一个窗格，底栏 P1 / P2 等按钮选择窗格。只按宽度切换呈现；键盘引起的高度变化不改写桌面分屏树。焦点和临时放大也不改写分屏几何。

布局存入按 Hub、用户和 namespace 区分的 localStorage，只包含资源引用、名称和几何。工作区没有新增聊天正文数据库。布局目前只在当前浏览器保存，尚未由 Hub 跨设备共享。

## 生命周期改动

- `SessionPaneController` 复用原单会话入口的发送、恢复、上传及查询逻辑。`PaneContext` 将导航和快捷键限制在相应窗格，晚到的恢复结果不能替换后续绑定的会话。
- 离开工作区、手机切窗格和结构变动前保存阅读书签；原历史滚动算法继续拥有位置。FlexLayout 模型重用原有视图，拖动和 resize 不重挂可见输入框。
- 当前可见会话组成一个集合；现有全局 SSE 同时向这些会话投递正文，没有为每个窗格增加一条 SSE。预热不覆盖可见会话的历史窗口。已挂载的 SessionPresentation 不被最近缓存逐出。
- 问题回答草稿和在途发送错误按会话保存。发送请求失败时，即使原窗格已隐藏，回来仍能恢复错误与草稿，不自动重发。
- 工作区终端使用稳定 terminalId，仍调用现有终端链路。Hub 拒绝另一个仍连接的浏览器抢占该终端，原控制端 detach 后才允许重新绑定。关闭视图不发送 stop 或 terminate。
